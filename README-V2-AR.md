# كوكب المناخ — الإصدار الثاني V2 🌍

**تحديث جاهز لمشروع Cloudflare Workers الحالي `mute-silence-5660` المرتبط بمستودع GitHub.**

## ماذا تغير؟

- واجهة RTL عربية جديدة بهوية داكنة، وبداخلها الشعار المرسل من مالك الصفحة بصيغتي WebP للعرض السريع وPNG لمعاينات فيسبوك.
- علامات تبويب مستقلة (الرئيسية / طقس المدن / المقالات والخرائط / الفضاء / أرشيف القدس). روابطها تعتمد `#weather`, `#journal`, `#space`, `#archive` فتفتح مباشرة وتعمل دون خادم خلفي.
- قسم الطقس ببحث وفلاتر دول، وبيانات **Open-Meteo وقت الطلب**، توقعات الأيام السبعة، الإحساس الفعلي والرطوبة والرياح والأشعة فوق البنفسجية والمطر. يوجد تخزين في جلسة المتصفح لمدة 10 دقائق. مؤشر الملابس والتنقل والمدارس والصحة العامة **إرشادي آلي مشتق من عتبات**، ومقياس الخطورة من 100 **نسبي وليس احتمالات مئوية فعلية** وليس قرارًا رسميًا أو تشخيصًا. عند تعطل المصدر تظهر حالة عدم التوفر، لا أرقام مصطنعة.
- مكتبة فضاء تتضمن 8 كواكب، 4 أقمار، 3 نجوم، 3 مجرات، ومحطتين فضائيتين ومرصد جيمس ويب، مع معلومات وروابط لكل موضوع إلى ويكيبيديا. المشهد التفاعلي Three.js يدعم الدوران والاختيار وسرعة 1×/2×/4×. أحجام المدارات والسرعات غير علمية من حيث المقياس. المجسمات تستخدم خامات Solar System Scope المرخصة CC BY 4.0 عند توفر الشبكة؛ وإلا ألوان احتياطية. إذا تعذر WebGL/تحميل Three.js تظهر واجهة اختيار مبسطة.
- دمج المقالات والخرائط في مجلة واحدة بفلاتر؛ 3 مقالات **تجريبية قديمة** مرفقة، ولم تُنسخ منشورات فيسبوك تلقائيًا. انشر محتواك من Pages CMS كما في V1.
- أرشيف **خاص بالقدس** من 1950 إلى شتاء 2025–2026، يعرض 77 موسمًا متتابعًا. تمت كتابة **86 حالة** شتوية من كانون الأول وكانون الثاني وشباط من صفحة Arab4Climate المقدمة من المستخدم، منها **46 موسمًا** تتضمن حالات مدرجة. يتدرج التراكم المسجل إلى 0–5، 6–10، 11–25، 26–40، أكثر من 40 سم؛ التراكم غير المذكر محفوظ `null`. عدم ظهور حادثة سنة ما لا يعني أنها كانت خالية من الثلوج. المصدر مؤرخ في 2020 وليس جامعًا للسنوات حتى 2026. الواجهة تحافظ على 2020–2026 بلا بيانات مختلقة.
- صفحات المقالات تظهر بوسوم Open Graph وصورة PNG للمعاينة على فيسبوك. قيمة `SITE_URL` اختيارية، وافتراضيًا تستعمل رابط Worker الذي ظهر في المحادثة.

## نشر التحديث على مشروع GitHub + Workers الموجود (لا تنشئ مشروعًا ثانيًا)

1. **احتفظ بنسخة احتياطية من مستودع V1** قبل استبدال ملفات المشروع.
2. فكّ ضغط `Kawkab_AlMonakh_V2_GitHub_Workers_Source.zip` ثم انقل **محتويات المجلد** (وليس ZIP نفسه) إلى جذر المستودع الذي يتصل به Cloudflare. أهم العناصر: `site/`, `content/`, `data/`, `scripts/`, `package.json`, `.pages.yml`, `wrangler.jsonc`.
3. راجع `wrangler.jsonc`: الاسم الافتراضي `mute-silence-5660`. إذا كان Worker لديك اسمه مختلفًا فغيّر الاسم ليتطابق بالضبط.
4. في Cloudflare Workers > مشروعك > Settings > Builds: `Build command = npm run build` و`Deploy command = npx wrangler deploy` و`Root directory = /` (جذر المستودع). إذا كان الإعداد نفسه موجودًا فلا تغيره.
5. احفظ التعديل في فرع GitHub المرتبط بالنشر (غالبًا `main`). راقب Deployments للتأكد من البناء. رابط موقعك **لا يتغير** ما دمت على Worker نفسه.
6. افتح الرابط وتحقق من تبويبات `#archive`, `#space`, `#weather`. إذا فشل البناء اتجه إلى سجل الأخطاء في Deployments.
7. للمشاركة الصحيحة على فيسبوك حدد متغير البناء **SITE_URL** بعنوان موقعك العام بدون `/` أخير، مثال: `https://mute-silence-5660.amardrbala1.workers.dev`، ثم أعد البناء. القيمة نفسها مستخدمة افتراضيًا في `scripts/build.mjs` ويمكن تعديلها لاحقًا.

> **مهم جدًا للهاتف:** واجهة GitHub على الهاتف قد لا تتيح رفع هيكل مجلدات كامل بسهولة. استخدم متصفح الكمبيوتر أو وضع Desktop site مع وسيلة ترفع المجلدات كما هي، أو Git على الكمبيوتر/Termux. رفع ZIP كملف واحد إلى المستودع لا يشغّل الموقع.

### تشغيل واختبار محلي

```bash
npm run build:offline
# افتح dist عن طريق خادم محلي، مثل:
npx serve dist
```

عند نشر العادية `npm run build` يحاول تحديث قائمة المواقع الجغرافية من GeoNames عبر GitHub وصولًا إلى **1000 موقع**. في حال تعذر تنزيل البيانات يتراجع إلى **100 موقع حقيقي داخل المشروع**. لن نعرض عددًا مضخمًا على الشاشة؛ العداد يقرأ العدد الفعلي.

### أين أضيف المحتوى؟

- **المقالات:** `content/posts/*.md` في لوحة Pages CMS؛ الرابط يصبح `/articles/SLUG/`.
- **الخرائط:** `content/maps/*.json` في Pages CMS، مع الصورة والنموذج والطبقة والتاريخ. لن يظهر SVG توضيحي على أنه توقع حقيقي.
- **أرشيف القدس:** البيانات الأصلية موجودة في `data/jerusalem-snow.json`. لإضافة حالات موثوقة من لوحة Pages CMS افتح «أرشيف ثلوج القدس (إضافات موثقة)»؛ كل ملف جديد يدمج عند البناء في أرشيف الموقع، مع مصدر إلزامي. يمكن إضافة السجلات أيضًا إلى `content/jerusalem/*.json`. لا تشغّل `npm run archive:seed` بعد إضافة بياناتك لأنه يعيد إنشاء الملف الأساسي التاريخي، لكن ملفات CMS لا تتأثر.
- **صفحة فيسبوك:** رابطها ضمن أسفل الموقع. **المنشورات لا تُجلب ولا تُنشر تلقائيًا** من فيسبوك في V2؛ إدارتها ما زالت يدوية من لوحة المحتوى، ومشاركة الروابط على فيسبوك متاحة.
